## Архитектурное разделение и принципы проектирования
Проект построен с учётом следующих принципов:

Проект построен с учётом следующих принципов:

- **MVC (Model-View-Controller)** — архитектура, разделяющая логику работы с данными, отображение и управление взаимодействием.

    - Model: содержит логику и данные, с которыми работает приложение. Пример: модели для товаров и корзины.
    - View: отвечает за отображение данных на UI. Пример: карточки товаров, корзина.
    - Controller: управляет взаимодействием между Model и View, обновляет UI в зависимости от действий пользователя.

- **Разделение на слои** (Separation of Concerns): каждый слой отвечает за свою задачу, что упрощает поддержку и тестирование системы.

- **Принцип единственной ответственности (Single Responsibility Principle)**: 
    - Каждый класс отвечает только за свою задачу (например, ProductCard только отображает товар, а ProductModel только хранит данные о товаре).

- **Слабое связывание (Loose Coupling)**:
	- Взаимодействие между компонентами осуществляется через передачу данных (например, через параметры или события), а не через жесткое создание экземпляров внутри классов. Это позволяет изменять и тестировать отдельные части системы независимо друг от друга.

## Типизация и модели данных
Все типы данных собраны в файле src/types/index.ts , что позволяет централизованно управлять интерфейсами и типами. Типы разделены по функциональным группам:

#### Модели API: описывают данные, получаемые от сервера:

```
export interface IApiProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

export interface IApiProductList {
  total: number;
  items: IApiProduct[];
}
```
#### UI модели: описывают данные, используемые в интерфейсе:

```
export interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

export interface ICustomerData {
  payment: string;
  email: string;
  phone: string;
  address?: string;
}

export interface IOrder {
  products: IProduct[];
  customerData: ICustomerData;
  total: number;
}
```
Прочие типы: для описания пропсов компонентов, навигационных событий и т.д.


## API эндпоинты
#### 1. Список товаров
* Метод: GET
* Эндпоинт: {{baseUrl}}/product/
* Пример успешного ответа (200 OK):

```
{
  "total": 10,
  "items": [
    {
      "id": "854cef69-976d-4c2a-a18c-2aa45046c390",
      "description": "If you plan to solve tasks on the simulator, buy two.",
      "image": "/5_Dots.svg",
      "title": "+1 hour in a day",
      "category": "soft-skills",
      "price": 750
    },
    ...
  ]
}
```
#### 2. Товар
* Метод: GET
* Эндпоинт: {{baseUrl}}/product/{id}
* Пример успешного ответа (200 OK):

```
{
  "id": "854cef69-976d-4c2a-a18c-2aa45046c390",
  "description": "If you plan to solve tasks on the simulator, buy two.",
  "image": "/5_Dots.svg",
  "title": "+1 hour in a day",
  "category": "soft-skills",
  "price": 750
}
```
Ответ при ошибке (404 Not Found):

```
{
  "error": "NotFound"
}
```
#### 3. Заказ
* Метод: POST
* Эндпоинт: {{baseUrl}}/order
* Пример тела запроса:

```
{
  "payment": "online",
  "email": "test@test.com",
  "phone": "+71234567890",
  "address": "Spb Vosstania 1",
  "total": 2200,
  "items": [
    "854cef69-976d-4c2a-a18c-2aa45046c390",
    "c101ab44-ed99-4a54-990d-47aa2bb4e7d9"
  ]
}
```
Пример успешного ответа (200 OK):

```
{
  "id": "28c57cb4-3002-4445-8aa1-2a06a5055ae5",
  "total": 2200
}
```
Ошибки (400 Bad Request):

- Товар не найден:

```
{
  "error": "Product with id c101ab44-ed99-4a54-990d-47aa2bb4e7d not found"
}
```
- Неверная сумма заказа:

```
{
  "error": "Incorrect order total"
}
```
- Не указан адрес:

```
{
  "error": "Address not provided"
}
```

## Компоненты и страницы
#### Компоненты
#### Api
Класс для работы с HTTP-запросами (GET, POST, PUT, DELETE). Отвечает за отправку запросов к серверу, обработку ответов и ошибок.

#### EventEmitter
Реализация брокера событий для обмена сообщениями между компонентами приложения. Поддерживает стандартные подписки, а также подписки, срабатывающие один раз.

#### Cart
Модель для работы с корзиной. Хранит список добавленных товаров, рассчитывает общую сумму заказа и оповещает о изменениях через EventEmitter.

#### CustomerData и Order
Модели для хранения данных покупателя и оформления заказа.

#### BaseForm
Абстрактный класс для переиспользуемых форм ввода (например, для заказа и ввода контактных данных). Обеспечивает общую логику валидации и обработки событий.

#### CartView
Отвечает за отображение содержимого корзины. Рендерит список товаров, общую сумму и предоставляет возможность удаления товара или перехода к оформлению заказа.

#### ProductCard
Отвечает за отображение краткой информации о товаре (название, изображение, цена, категория). При клике вызывает функцию для открытия подробного представления товара.

#### ProductDetail
Отображает подробную информацию о товаре (описание, изображение, цена и т.д.) в модальном окне. Включает возможность добавления товара в корзину.

#### ContactsForm и OrderForm
Формы для ввода контактных данных (email, телефон) и информации для оформления заказа (способ оплаты, адрес). Наследуются от BaseForm и реализуют специфическую валидацию и обработку событий.

#### OrderSuccess
Отображает сообщение об успешном оформлении заказа, показывая списанную сумму. Предоставляет возможность закрыть модальное окно.

#### Modal
Компонент для отображения модальных окон. Используется для показа подробностей товара, корзины и форм оформления заказа.

## Страницы и модальные окна
#### Главная страница (index.html):
Отображает каталог товаров и заголовок с кнопкой для открытия корзины. Точка входа приложения, где инициализируются контроллеры и загружаются товары.

#### Модальное окно (Modal):
Единый компонент для отображения различных форм и деталей. Используется для:

#### ProductDetail: 
подробное представление товара с кнопкой добавления в корзину.

#### CartView: 
просмотр содержимого корзины с возможностью удаления товаров и перехода к оформлению заказа.

#### OrderForm: 
форма для выбора способа оплаты и ввода адреса.

#### ContactsForm: 
форма для ввода контактных данных (телефон, email).

#### OrderSuccess: 
подтверждение успешного оформления заказа.

#### Контроллеры:

#### ProductController: 
управляет загрузкой товаров с сервера, рендерингом галереи и открытием модального окна с подробной информацией о товаре.

#### CartController: 
отвечает за добавление/удаление товаров из корзины и открытие модального окна с корзиной.

#### OrderController: 
управляет процессом оформления заказа, включая последовательное отображение форм заказа и обработку отправки данных на сервер.
